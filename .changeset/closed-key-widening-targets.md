The `oxlint/anti-slop` rule `no-known-value-widening` now classifies `Record<K, V>` and mapped types by their key, whether written inline, as `Record` or as a mapped type, behind a local alias, or under `Partial`. A local alias whose key is a finite literal union, such as `type Table = Partial<Record<"a" | "b", string>>`, is no longer reported, matching the equivalent mapped type. Generic aliases are reported as generic containers only when their resolved key is open, so `type PerKey<T> = { [K in "a" | "b"]?: T }` and homomorphic aliases such as `{ [K in keyof T]: T[K] }` applied to a closed object are no longer reported, while the same aliases applied to an open dictionary still are. An inline closed-key annotation is still reported, now as an `inline mapped` type instead of an `open dictionary`. Keys that admit arbitrary values, such as `string`, `any`, `PropertyKey`, `keyof` an open dictionary, a union containing `string`, or a mapped type remapped with `as string`, are still reported as open dictionaries, including through `Omit` of literal keys and through `Pick` with an open key. Type arguments of nested alias applications now resolve in the scope where they are written, which also applies to `no-unsafe-dictionary-type`.
